# SPEC-v1.2.md
## ggplot2 extended (companion) — v1.2 Technical Specification

### 1. Overview

- **App name**: ggplot2 extended (companion)
- **One-line description**: v1.2 is a polish release — connection stability, mobile UX, desktop layout rhythm, the `is_essential → is_featured` rename, a light-touch brand accent, an accessibility floor, and an end-to-end smoke test. No new feature areas; no architectural overhauls.
- **Technology**: R Shiny (golem framework) — unchanged.
- **Target deployment**: Docker on Google Cloud Run (region `europe-north1`, service `ggplot2-companion`) — unchanged.
- **Scope**: This spec covers only v1.2 changes layered on top of the v1.1 baseline (Google Form, archived packages, non-CRAN enrichment, version label rename). `SPEC.md` (v1.0) and `SPEC-v1.1.md` remain the reference for everything not touched here. Where v1.2 modifies existing code, the affected files and functions are named explicitly.
- **Non-goals** (carried from REQUIREMENTS v1.2 §1 and §10): tech-stack rewrite, SaaS-product trappings (analytics, SEO, Open Graph imagery, conversion tracking, A/B testing), full brand identity (logo, wordmark, custom typography), mobile-first redesign, snapshot-based visual regression, comprehensive WCAG 2.2 AAA audit.

### 5. UI Specification — Changes

#### 5.1 Layout restructure: per-view page shape (REQUIREMENTS §2.3.1)

**Decision (Q6): Per-view layout swap, not conditional-render of the sidebar.** Rationale: architecturally cleaner; eliminates the entire "sidebar on the detail view" question (including its mobile-bottom-dumping failure mode) by removing the sidebar from the DOM on detail. The extra width on detail is a free win.

**Pattern**: the `app_ui()` top-level return is a `tagList` with `uiOutput("main_page")` as its only body element. Each page helper returns a **complete** `bslib::page_sidebar()` or `bslib::page_fillable()` (not a fragment to embed inside another page) — `renderUI` dispatches one or the other.

`R/app_ui.R` changes:

```r
app_ui <- function(request) {
  tagList(
    golem_add_external_resources(),
    shiny::uiOutput("main_page")
  )
}
```

`R/app_server.R` gains an output that chooses the page shape based on `selected_package()`:

```r
output$main_page <- shiny::renderUI({
  if (is.null(selected_package())) {
    render_browse_page()   # returns bslib::page_sidebar(...) with filters + mod_browse_ui("browse")
  } else {
    render_detail_page()   # returns bslib::page_fillable(...) with mod_detail_ui("detail")
  }
})
# Keep rendered when hidden so the reactable state survives a view switch
shiny::outputOptions(output, "main_page", suspendWhenHidden = FALSE)
```

Both `render_browse_page()` and `render_detail_page()` are new helper functions in `R/app_ui.R`. Both pages share the same `title`, `theme = app_theme()`, the `input_dark_mode` toggle in the navbar (§5.4), and the header/footer. They differ only in the sidebar slot.

**Consequence**: the `conditionalPanel(condition = "!output.show_detail")` / `output.show_detail` plumbing is removed. The module UIs (`mod_browse_ui`, `mod_detail_ui`) are still mounted once — they're placed inside the two page helpers.

**Critical — module server lifecycle** (avoid a common mistake): the module **server** calls (`mod_browse_server("browse")`, `mod_detail_server("detail")`, `mod_sidebar_server("sidebar")`, `mod_header_server("header")`, `mod_footer_server("footer")`, `mod_reconnect_server("reconnect")`) stay at the top level of `app_server()` and run **exactly once** at session start — exactly as they do in the v1.1 baseline. Only the UI placements move into the page helpers. **Do not** move any `mod_*_server()` calls into the `renderUI` — doing so would re-register observers on every view switch and drop reactive state (selected row, scroll position, filter URL sync). `renderUI` re-evaluates the UI on each view switch; the module servers must not.

#### 5.2 Connection stability — keep-alive and disconnect handling (REQUIREMENTS §2.1)

New module: **`R/mod_reconnect.R`** — owns the keep-alive ping, the disconnect-overlay replacement, and the session-expired card.

##### 5.2.1 Client-side keep-alive (REQUIREMENTS §2.1.4)

- **Interval**: 270 seconds (4.5 min) — keeps the WebSocket warm without rounding up to a full 5-min cache window and gives ~5× margin before Cloud Run's 30-min idle timeout. Q2 resolved.
- **Guard**: `document.visibilityState === "visible"`. When the tab is `hidden`, the interval's callback short-circuits; no ping fires. This preserves scale-to-zero when a user walks away with the tab backgrounded.
- **Mechanism**: a round-trip `Shiny.setInputValue("keep_alive", Date.now(), {priority: "event"})` fired from a `setInterval`. The server-side observer is a no-op that merely touches session activity. Nothing about the business logic depends on the ping.

JS lives in a new file: `inst/app/www/keep-alive.js` (bundled via golem's `add_resource_path`).

```js
(function () {
  var INTERVAL_MS = 270 * 1000;  // 4.5 minutes
  setInterval(function () {
    if (document.visibilityState !== "visible") return;
    if (typeof Shiny === "undefined" || !Shiny.setInputValue) return;
    Shiny.setInputValue("keep_alive", Date.now(), { priority: "event" });
  }, INTERVAL_MS);
})();
```

Server-side (inside `mod_reconnect_server` or `app_server`):

```r
shiny::observeEvent(input$keep_alive, {
  # No-op — receiving the event is enough to reset session-activity timers.
}, ignoreInit = TRUE)
```

##### 5.2.2 Disconnect-overlay replacement (REQUIREMENTS §2.1.5)

Shiny emits a `shiny:disconnected` event on the document when the WebSocket drops and injects the grey overlay. The keep-alive JS also:

1. Listens for `shiny:disconnected`.
2. Removes Shiny's default `#shiny-disconnected-overlay` element.
3. Injects the session-expired card into the page body.

The card markup is rendered server-side as a hidden `div` and revealed by JS on disconnect — this guarantees theme-awareness (bslib classes and `data-bs-theme`) without requiring the JS to rebuild the UI.

Markup (rendered into `app_ui.R` inside the outer `tagList`, initially hidden):

```r
htmltools::tags$div(
  id = "reconnect-card",
  class = "reconnect-card d-none",
  role = "alert",
  `aria-live` = "assertive",
  bslib::card(
    class = "shadow-lg",
    bslib::card_header(htmltools::tags$h3("Your session expired", class = "m-0")),
    bslib::card_body(
      htmltools::tags$p(
        "You've been away for a while and the connection to the server timed out. ",
        "Reload the page to pick up where you left off — your filters will reset to defaults."
      ),
      htmltools::tags$button(
        type = "button",
        class = "btn btn-primary",
        onclick = "window.location.reload()",
        "Reload the app"
      )
    )
  )
)
```

JS additions (same `keep-alive.js`):

```js
document.addEventListener("shiny:disconnected", function () {

    card.classList.remove("d-none");

```

##### 5.2.3 Server-side session timeout (REQUIREMENTS §2.1.3)

**Mechanism clarification.** Shiny has no built-in "idle session timeout" R option — `shiny.session_timeout` does not exist. What actually governs idle survival on Cloud Run is the **WebSocket request timeout at the HTTP layer**, set by `gcloud run deploy --timeout`. While the WebSocket stays open, the Shiny session stays alive; when Cloud Run closes the WebSocket (after the configured `--timeout` of idle time), Shiny emits `shiny:disconnected` and our reconnect card (§5.2.2) takes over.

So the 30-min idle survival is a **one-flag Cloud Run change**, plus the client-side keep-alive (§5.2.1) that prevents premature closure while the tab is visible. No R `options()` call is needed.

- `.github/workflows/pipeline.yml` — append `--timeout 1800` to the `gcloud run deploy` command (already listed in §4 and §2.3).
- `inst/golem-config.yml` — exposes the keep-alive interval for the JS layer via a Shiny custom message on session start (so changing the interval does not require rebuilding the Docker image; only a config commit + redeploy):

```yaml
default:
  golem_name: ggplot2.extended.companion
  golem_version: 0.0.0.9000
  app_prod: no
  google_form_url: "https://forms.gle/RkviFqae7aAdUA4q9"
  cloud_run_timeout_seconds: 1800      # NEW — documented here; applied by pipeline.yml
  keep_alive_interval_seconds: 270     # NEW — pushed to JS at session start

production:
  app_prod: yes
```

`R/app_server.R` adds a one-liner that pushes the config to the client so `keep-alive.js` can read it:

```r

  "set_keep_alive_interval",
  list(ms = 1000 * get_golem_config("keep_alive_interval_seconds"))
)
```

`inst/app/www/keep-alive.js` uses the pushed value (falling back to 270 s):

```js

Shiny.addCustomMessageHandler("set_keep_alive_interval", function (msg) {
  INTERVAL_MS = msg.ms;
  // (re)schedule timer — implementation detail
});
```

**Rollback lever** (REQUIREMENTS §4.3): if billing escalates post-launch, reduce the idle window by editing one YAML value (`cloud_run_timeout_seconds: 900`) and the corresponding flag in `pipeline.yml` — no image rebuild needed; only a re-deploy. The keep-alive interval can be tuned the same way without redeploying the image (just config + workflow re-run).

- `.github/workflows/pipeline.yml` `gcloud run deploy` — append `--timeout 1800`.

##### 5.2.4 Filter state preservation across reconnect (REQUIREMENTS §2.1.6, nice-to-have)

**Decision: in-scope at minimum viable.** The v1.1 code already pushes `?package=<name>` to the URL on detail navigation. v1.2 extends this pattern to sidebar filters (browse view only).

- `R/app_server.R` adds an observer that writes filter state into the URL query string (debounced 500 ms):
  - `?category=...&cran=...&license=...&featured=...&added=...&updated=...&archived=...`
  - Empty/default values are omitted from the URL.
- On startup, `parseQueryString()` populates `updateSelectInput()` / `updateCheckboxInput()` calls for each recognised key before `sidebar_values` is first read.
- Combined with the reconnect flow: when the user clicks "Reload the app," the browser retains the query string, so filters come back.

If during implementation the URL-syncing introduces flicker or reactive loops, fall back to `sessionStorage` (same list of keys, JSON-serialised). Either approach satisfies the requirement.

#### 5.4 Theme toggle (REQUIREMENTS §2.3.2)

The existing `bslib::input_dark_mode(id = "colour_mode", mode = "dark")` is already in `app_ui.R` line 38. v1.2 changes:

1. **Remove the explicit `mode = "dark"` argument.** Without `mode`, `input_dark_mode()` falls back to `prefers-color-scheme` for the first visit, exactly as REQUIREMENTS §2.3.2 requires.
2. **Placement**: `input_dark_mode()` is already positioned as the last direct argument inside the `page_sidebar()` header area, which bslib renders top-right in the navbar. No change needed.
3. **Persistence**: `input_dark_mode()` persists the user's choice in `localStorage` out of the box.
4. **Live OS sync until explicit choice** (Q5): requires a small JS addition in `inst/app/www/dark-mode-icons.js` (which already exists in the repo, so extend it rather than create a new file):

```js
// Follow OS changes until the user makes an explicit click.
(function () {
  var EXPLICIT_KEY = "bslib-colour-mode-explicit";
  if (localStorage.getItem(EXPLICIT_KEY) === "true") return;

  var mql = window.matchMedia("(prefers-color-scheme: dark)");
  mql.addEventListener("change", function (e) {
    if (localStorage.getItem(EXPLICIT_KEY) === "true") return;
    var mode = e.matches ? "dark" : "light";
    document.documentElement.setAttribute("data-bs-theme", mode);
  });

  document.addEventListener("click", function (e) {
    var target = e.target.closest("[id='colour_mode']");
    if (target) localStorage.setItem(EXPLICIT_KEY, "true");
  });
})();
```

```r
test_that("happy path: load → filter → click package → return", {
  skip_on_cran()
  skip_if_not_installed("shinytest2")
  skip_if_not_installed("chromote")

  app <- shinytest2::AppDriver$new(
    app_dir = testthat::test_path("../../"),   # project root
    name = "v1-2-happy-path",
    width = 1440, height = 900,
    load_timeout = 30 * 1000
  )

  # 1. App loads
  app$wait_for_idle()

  # 2. Package table renders with a reasonable number of rows
  row_count <- app$get_js(
    "document.querySelectorAll('.rt-tbody .rt-tr').length"
  )
  testthat::expect_gt(row_count, 100)   # we have ~455 packages

  # 3. Apply a category filter; row count decreases
  app$set_inputs(`sidebar-category` = "geoms")
  app$wait_for_idle()
  filtered_count <- app$get_js(
    "document.querySelectorAll('.rt-tbody .rt-tr').length"
  )
  testthat::expect_lt(filtered_count, row_count)

  # 4. Click a package row (use Shiny.setInputValue directly — the same
  #    mechanism the package-link onclick uses, avoiding click-coordinate fragility)
  first_pkg <- app$get_js(
    "document.querySelector('.rt-tbody .package-link').textContent"
  )
  app$run_js(sprintf(
    "Shiny.setInputValue('browse-selected_pkg', '%s', {priority: 'event'})",
    first_pkg
  ))
  app$wait_for_idle()

  # 5. Detail view loads and displays the right package name
  detail_heading <- app$get_js(
    "document.querySelector('#main-content h1, #main-content h2').textContent"
  )
  testthat::expect_match(detail_heading, first_pkg, fixed = TRUE)

  # 6. Return to browse view via Back button
  app$click("detail-back_btn_top")
  app$wait_for_idle()
  on_browse <- app$get_js(
    "document.querySelector('.rt-tbody') !== null"
  )
  testthat::expect_true(on_browse)

  app$stop()
})
```

### 12. Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Keep-alive ping keeps container alive when tab is backgrounded (scale-to-zero defeated) | Low | Medium | Page Visibility API guard in `keep-alive.js`; manual DevTools verification in M2 DoD; rollback lever 30→15 min |
| 30-min Cloud Run request timeout causes unexpected billing growth | Medium | Low | $20/month billing alert; 2–4 week monitoring post-launch; rollback lever in `golem-config.yml` |
| Per-view layout swap (§5.1) introduces flicker when toggling browse↔detail | Low | Medium | `uiOutput("main_page")` + `outputOptions(suspendWhenHidden = FALSE)`; manual verification in M1 DoD |
| JS-based mobile column hiding breaks if reactable reindexes columns | Medium | Low | Fallback plan to class-based hiding via `colDef(className = "rt-col-mobile-hide")`; documented in §5.6 |
| `shinytest2` flakiness in CI | Medium | Medium | `wait_for_idle()` at every step; ≥30 s load timeout; use `Shiny.setInputValue` not click-coordinates; fix flakes, do not skip |
| localStorage key collision with other bslib sites on same domain | Very Low | Low | Namespaced keys (`intro-accordion-seen`, `bslib-colour-mode-explicit`) |
| Filter-state URL sync triggers reactive loop on page load | Medium | Low | Debounce writes by 500 ms; skip write if URL already matches; guard with `once = TRUE` on startup parse |
| Hard JSON rename breaks an unknown external consumer | Low | Low | Release-note callout; single version of truth in README; v1.2 is young enough that breakage is acceptable |
| Filter state URL encoding conflicts with `?package=<name>` deep-link | Low | Medium | Merge both key sets into one query string; browse view uses filter keys, detail view uses `package` key only |

#### C. Glossary (v1.2 additions)

| Term | Definition |
|---|---|
| Featured (in the book) | Packages covered in the companion book — the maintainer's recommended starting set. Replaces "Essential" terminology from v1.0/v1.1. |
| Keep-alive | Client-side periodic message that keeps the Shiny WebSocket warm while the tab is visible; respects the Page Visibility API. |
| Reconnect card | The session-expired UI that replaces Shiny's default grey disconnected overlay. Theme-aware, accessible, single call-to-action. |
| Page Visibility API | Browser API (`document.visibilityState`) used to suppress keep-alive pings when the tab is hidden. |
| Scale-to-zero | Cloud Run configuration (`--min-instances 0`) where the container count drops to zero when idle. Preserves the cost model. |
| Off-canvas drawer | Mobile sidebar pattern where filters slide in from the side over a dimmed background, dismissable on click-outside or Escape. |
